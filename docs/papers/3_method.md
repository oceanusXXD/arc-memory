# 3 方法：查询分布感知的持久长期记忆构造

## 3.1 问题定义：写入阶段的联合结构–内容决策

**系统组件。** 长期记忆系统由以下冻结组件构成：构建器 \(G\)（读取序列化输入、按指定 schema 产出记忆块）、确定性更新接口 \(\operatorname{Update}\)（把记忆块写入持久记忆）、检索器 \(\mathcal R\) 与回答模型 \(F\)（查询阶段读取路径）。唯一可学习的组件是写入策略 \(H_\theta\)。第 \(i\) 个记忆更新单元由写入前持久记忆 \(\mathcal M_i^{-}\)、新到达历史批次 \(X_i\) 与构建输入预算 \(b>0\) 组成。固定的、与测试查询无关的候选生成器 \(\mathcal C\) 根据新历史及其与已有记忆的局部关系形成候选来源集合

\[
E_i=\mathcal C(X_i,\mathcal M_i^{-})
=\{e_{i1},\ldots,e_{n_i}\}.
\tag{1}
\]

\(E_i\) 仅由写入时可见的信息产生，可包含新历史中的原始来源单元，以及为去重、冲突处理或关联更新而从已有记忆取得的有限邻域；测试查询不参与。每个来源保留原始文本与可观测元数据（来源标识、会话、时间、长度）。

**决策与部署过程。** ARC 在 \(E_i\) 上联合决定哪些来源值得长期保留、以何种组织架构组织。完整结构化方案记为 \((S,g)\)，其中

\[
\mathcal G=\
\{\mathrm{Flat},\mathrm{Chain},\mathrm{Tree},\mathrm{Graph},\mathrm{Cluster}\},
\qquad
g\in\mathcal G,\quad S\subseteq E_i.
\]

写入时策略输出一个方案，冻结构建器执行恰好一次构造并写入：

\[
(\hat S_i,\hat g_i)=H_\theta(E_i,b),\qquad
m_i=\operatorname{Build}_{\hat g_i}(\hat S_i;G),\qquad
\mathcal M_i^{+}=\operatorname{Update}(\mathcal M_i^{-},m_i).
\tag{2}
\]

此后查询不再触发任何结构或内容决策：对任意未来查询 \(q\)，固定读取器取得证据、冻结回答模型作答，

\[
R_q=\mathcal R(q,\mathcal M_i^{+}),\qquad
\hat y_q=F(q,R_q).
\tag{3}
\]

\(q\) 是记忆的消费者，而不是写入策略的输入。

**部署目标（形式化）。** 记 \(U_i(g,S)\in[0,1]\) 为持久记忆 \(\mathcal M_i^{g,S}\) 对未来查询分布的期望效用（§3.3 以代表性查询集实例化其估计），\(C_i(g,S)\) 为其生命周期成本（式（7））。写入策略 \(\pi\) 是方案上关于 \(\sigma(E_i,b)\) 可测、支撑于可行集 \(\mathcal F_b=\{(S,g):T_g(S)\le b\}\) 的任意条件分布。写入阶段理想上求解的 oracle 问题为

\[
\pi_i^{*}\ \in\ \operatorname*{arg\,max}_{\pi}\
\mathbb E_{(S,g)\sim\pi}\!\left[U_i(g,S)\right]
\qquad\text{s.t.}\quad
\operatorname{supp}(\pi)\subseteq\mathcal F_b,
\]

并在效用同等的策略之间偏好更低的生命周期成本。该问题在写入阶段设定下不可直接求解，障碍有三：

- **(O1) 执行定义的目标。** \(U_i\) 与 \(C_i\) 没有解析形式：评估一个方案需要真实构造记忆并真实回答查询，只有昂贵的 oracle 访问，而非可微函数。
- **(O2) 写入时信息约束。** \(\pi\) 不得依赖任何未来查询；查询相关的量只能以分布层面的先验进入。这是 ARC“查询分布感知”的精确含义：查询分布仅用于离线的价值估计与监督编译，从不进入 \(H_\theta\)、构建器或部署写入路径。
- **(O3) 目标非唯一（一对多）。** 近优集合 \(\Pi_i^{*}=\{(S,g)\in\mathcal F_b:U_i(g,S)\ge\max U_i-\epsilon\}\) 通常含多个元素：替代证据、联合必要来源与一源多用使内容层映射一对多，架构选择进一步放大（§3.3；§8.5.1 给出诊断）。监督目标因此是一个**集合**而非单点；任何“从 \(\Pi_i^*\) 中挑一个”的单标签做法都等于强加一条任意的取舍规则，并丢弃其余元素携带的信息。

**ARC 的路径：把 oracle 编译为可认证监督。** ARC 对 O1–O3 的回答是两步归约。第一步，以**认证算子**替代 oracle：离线对每个候选方案真实执行，由三重冻结审核、双阈值与预算检查给出三态裁决（§3.3），得到已验证集（成功档案）\(\mathcal W_b(i)\subseteq\mathcal F_b\)：其中每个元素的效用都有认证下界（\(U_i\ge\tau_U\)、\(\operatorname{Cov}_i\ge\tau_{\mathrm{cov}}\)），O3 的多解性则直接表现为 \(|\mathcal W_b(i)|>1\)。第二步，以**档案上的边缘似然最大化**替代 oracle 优化：最大化 \(M_\theta(i,b)=\sum_{(S,g)\in\mathcal W_b(i)}P_\theta(S,g)\)。该归约不是启发式：采样解码下部署期望效用有认证下界 \(\mathbb E[U_i]\ge M_\theta(i,b)\cdot\tau_U\)（推论 1，§3.5.3），故训练目标最大化的是 oracle 目标的一个可证下界，而非代理指标；成本作为已认证方案之间的软偏好加入（式（25））。

**多解性是监督，不是噪声。** ARC 的出发点是一个关于冗余的观察：为构造或评价记忆，构建器必须读取候选历史的绝大部分，而这些读取在方案之间高度冗余。多个不同的来源子集可以产生同样忠实、同样完整的记忆：有的来源为同一事实提供替代证据，有的来源只有放在一起才可解释，有的来源同时支持多个事实。在写入阶段，该性质表现为：多个不同的 \((S,g)\) 方案产生长期价值相当的持久记忆。单标签范式把它压成噪声；ARC 把它变成监督本身（§3.3）。

**多解性的三个来源。** 替代证据、联合必要与一源多用都使内容层的映射一对多；架构层进一步放大这种多解性：同一来源集合可以组织为链、也可以组织为图，二者都可能通过认证。单标签监督则迫使在已验证方案中任选其一并丢弃其余：等价方案间出现任意选择，内容与结构被拆成互不负责的标签。

**摊销特性。** 写入阶段的另一侧约束来自“写一次、读多次”的摊销结构（§3.6、附录 G）：写入成本一次性、读取成本按查询发生，每查询摊销成本随服务查询数单调下降；其代价是放弃逐查询的内容适配，该权衡的边界由 §8.5.1 的重叠诊断与附录 E 的查询时上界消融量化。

**贡献。**（i）将长期记忆构造定义为写入阶段、查询分布感知的联合 \((S,g)\) 决策，并以显式写入预算约束真实序列化输入（§3.2）；（ii）提出执行认证的多正例监督编译，并给出**选择过拟合的定量控制**：档案是在候选域上对训练查询的多重比较结果，我们以覆盖率指数尾界＋查询无关认证层＋独立诊断档案抑制偶然通过（§3.3.4，命题 3）；（iii）提出内容优先（S→g）的序贯因子化与“保守–精确”两级预算掩码，并明确 \(S\) 与 \(g\) 各自如何获得信用分配（§3.4）；（iv）给出训练算法的选择与证明：以已验证成功终态的边缘化似然为目标（命题 4 的后验/EM 视角），证明其最大化部署期望效用的认证下界（推论 1），并以命题 6 建立“训练目标＝部署认证通过率”的闭环桥梁；（v）以摊销生命周期成本作为成功方案间的软偏好（命题 8），在两个基准上给出质量–成本前沿与行为诊断。算法总览见图 2（可绘制版见 figures.md）。

**图 2　ARC 算法总览。** 上：离线监督编译，候选 \((S,g)\) 经冻结构建器真实产出持久记忆，由代表性未来查询集合以“平均效用＋覆盖率＋三态审核”认证，形成多预算多正例档案；中：写入时内容优先策略，来源束在保守预算掩码下筛核心内容，架构头在精确预算检查下选组织方式，联合概率取 argmax 后执行一次 Build+Update；下：查询时固定读取路径，策略冻结、不再重建。

内容与结构必须作为同一个终态评价，但决策顺序采用**内容优先**：先决定哪些来源值得长期保留，再决定这些来源以何种结构组织。该顺序基于核心证据重叠的假设（§8.5.1 给出诊断）；同时，\(g\) 本质上是对已保留内容 \(S\) 的组织决策，例如时序链需要保留连接关键状态的中间事件，关系图需要保留跨实体的桥接证据，树和主题簇更依赖分支覆盖与主题完整性。相同来源集合在不同架构下可以产生不同效用，相同架构也可能需要不同来源组合，因此 ARC 不把 \(S\) 和 \(g\) 拆成两个独立标签，而以经过真实构造与下游验证的完整 \((S,g)\) 作为监督单位。

与 ARC 接近的工作在记忆生命周期中的决策位置并不相同。MemGAS 和 MAGMA 构建多粒度或多图持久表示，并在查询阶段进行粒度选择或图遍历；LeanMem 在写入时根据内容性质形成不同记忆类型，并在查询时动态选择类型和检索预算；FluxMem 学习基于交互特征的结构选择，并使用下游响应质量形成离线监督；BudgetMem 与 MESA 主要在查询阶段进行预算路由或多结构证据选择。[^memgas][^magma][^leanmem][^fluxmem][^budgetmem][^mesa] ARC 关注的对象是写入阶段的完整终态 \((S,g)\)：同一策略同时决定保留内容与组织结构，并在显式构建预算下把离线多方案搜索摊销为一次持久化构造。

## 3.2 可执行架构、写入预算与生命周期成本

### 3.2.1 架构类型与持久化实例

五种架构共享来源忠实性、时间限定和可追溯性要求，同时具有不同的组织约束。

| 架构 | 记忆组织与结构约束 |
|---|---|
| Flat | 独立事实或事件条目；保留来源与时间字段，条目间不显式建边。 |
| Chain | 事件或状态节点组成有序路径；相邻连接表达有来源支持的顺序或状态演进。 |
| Tree | 具有唯一根节点的连通无环层级；每个非根节点恰有一个父节点，上层概括可追溯到下层证据。 |
| Graph | 实体或事件节点通过有类型、可追溯的稀疏关系边连接；跨节点关系必须具有来源支持。 |
| Cluster | 条目被划分为互不重叠的主题组；每个条目归属一个组，组描述由其成员支持。 |

架构专属构建接口定义为

\[
\operatorname{Build}_g(S;G)
=
\operatorname{Post}_g\!\left(
G\!\left(\operatorname{Serialize}_g(S)\right)
\right).
\tag{4}
\]

\(\operatorname{Serialize}_g\) 由**公共来源序列化部分**（来源文本、元数据与公共字段）与**架构专属固定字段**（架构提示与 schema）组成；\(\operatorname{Post}_g\) 执行确定性解析和结构检查。模型 \(G\) 的参数与解码协议在不同架构间保持一致，节点抽取、层级划分和连接实例化由对应 schema 约束。ARC 学习架构类型与来源集合，具体 Chain 顺序、Tree 层级、Graph 边和 Cluster 分组由冻结构建器生成。所有生成语义都必须回溯到 \(S\) 中的来源，不允许为了满足结构外形补造事件、关系或时间信息。

\(\operatorname{Update}\) 负责将新构造块写入持久记忆，并按固定规则处理同源重复、版本替换和索引更新。它不包含可训练的架构选择，因此同一个 \((S,g)\) 在相同后端与配置下对应唯一的持久化执行路径。完整 schema、合法性检查与更新协议见附录 C。架构集合固定且小的理由有三：(i) 每种 \(g\) 配备确定性 \(\operatorname{Post}_g\) 合法性检查，硬可行性与认证可事前判定；(ii) 固定的小规模集合把候选域规模 \(|\Omega_i|\) 控制在命题 3 的对数级控制之内；(iii) 架构类型与架构内实例化分离，后者由冻结构建器完成，结构化学习与本框架正交，可作为未来扩展接入。

### 3.2.2 写入预算：事前硬可行性

硬预算约束构建模型实际接收的完整输入：

\[
T_g(S)=
\begin{cases}
0, & S=\varnothing,\\
\operatorname{Tok}_G\!\left(\operatorname{Serialize}_g(S)\right), & S\ne\varnothing,
\end{cases}
\qquad
T_g(S)\le b.
\tag{5}
\]

\(\operatorname{Tok}_G\) 使用构建模型 tokenizer，精确计算来源文本、元数据、架构提示、schema 和聊天模板。空集合跳过构建；非空方案满足 \(b+L_G\le I_G\)，其中 \(L_G\) 为构建输出上限，\(I_G\) 为上下文容量。由于 \(\operatorname{Serialize}_g\) 的架构专属字段是与 \(S\) 无关的固定字符串，记公共来源部分长度为 \(T^{\mathrm{src}}(S)\)、架构专属字段长度为 \(o_g\)，则在线来源阶段使用保守上界

\[
\hat T(S)=T^{\mathrm{src}}(S)+\max_{g'} o_{g'}.
\]

**命题 1（保守掩码正确性）。** 由 BPE 次可加性（引理 B.1：\(\operatorname{Tok}(x\oplus y)\le\operatorname{Tok}(x)+\operatorname{Tok}(y)\)），对一切 \(g\in\mathcal G\) 有 \(T_g(S)\le T^{\mathrm{src}}(S)+o_g\le\hat T(S)\)。因此以 \(\hat T(S_t\cup\{e_j\})\le b-m\)（裕量 \(m\ge0\)，仅用于抵御 tokenizer 版本漂移）作为来源阶段掩码时，任何完成的 \(S\) 对全部架构均满足精确可行性 \(T_g(S)\le b\)；最终 \((S,g)\) 方案另以式（5）精确确认，故硬预算约束在任何部署路径上均不被违反（引理 D.2）。完整证明、\(o_g\) 表与裕量/保守性敏感性见附录 B.3。

### 3.2.3 生命周期成本：真实使用 tokens

成本与预算是**两个不同的量**。预算 \(T_g\) 是**事前**的 tokenizer 计数，只回答“构建器能否接收该输入”，进入掩码与档案可达性；成本 \(C\) 是**事后**的、该 \((S,g)\) 在真实使用路径中实际消耗的生成 tokens，进入学习目标。二者不可互推：满足预算的方案仍可能因结构化输出冗长、回答上下文较长而昂贵。

记一次实际写入路径的生成调用集合为 \(\mathcal J_{\mathrm{wr}}(g,S)\)，写入成本为

\[
C^{\mathrm{wr}}(g,S)
=
\sum_{\ell\in\mathcal J_{\mathrm{wr}}(g,S)}
\left(t_\ell^{\mathrm{in}}+t_\ell^{\mathrm{out}}\right),
\tag{6}
\]

其中 \(t^{\mathrm{out}}\) 包含后端实际生成的推理 tokens。候选长期记忆还会影响后续读取长度和回答开销。对训练更新单元 \(i\) 的离线未来查询集合 \(\mathcal Q_i\)，定义每个未来查询的摊销生命周期成本

\[
C_i(g,S)
=
\frac{C^{\mathrm{wr}}(g,S)}{|\mathcal Q_i|}
+
\frac{1}{|\mathcal Q_i|}
\sum_{q\in\mathcal Q_i}
C^{\mathrm{rd}}\!\left(q;\mathcal M_i^{g,S}\right),
\tag{7}
\]

其中 \(\mathcal M_i^{g,S}\) 是应用该候选方案后的持久记忆，\(C^{\mathrm{rd}}\) 统计从查询进入到答案完成的**全部生成式调用**（读取后的回答输入/输出、系统触发的重试）的实际 tokens。所有计数取自后端 usage 日志，并与完整调用日志核对（协议见附录 B.7）；Retrieve 为非生成式索引访问，不计生成 tokens（延迟另行记录）。式（5）给出硬可行性，式（7）给出软偏好；训练只读取离线记录好的成本，不在优化阶段重新调用构建器或回答模型。

## 3.3 从真实持久化结果构造多正例监督

本节把 §3.1 的认证算子实例化为可执行协议：候选枚举（§3.3.1）→ 真实构造与长期价值评估（§3.3.2）→ 预算分层档案（§3.3.3）→ 选择偏差控制（§3.3.4）；§3.3.5 另给出成本感知的级联加速。算子的输出即已验证集 \(\mathcal W_b(i)\)：一个从执行记录到监督集合的确定性映射，不含任何可训练参数。层级关系：§3.3.1–3.3.4 是全量编译的主协议，全部主结果基于它；§3.3.5 是可选加速组件，入档规则保持逐字不变，其一致性评估见 §8.6。

### 3.3.1 训练更新单元与来源候选

一个训练更新单元记为

\[
\xi_i=
\left(
\mathcal M_i^{-},X_i,\mathcal Q_i,\{y_q^*:q\in\mathcal Q_i\}
\right),
\]

其中 \(X_i\) 是当前写入批次，\(\mathcal Q_i\) 是在该批次写入后用于评价长期记忆的未来查询集合。首先按式（1）生成与查询无关的 \(E_i\)。随后离线监督编译器利用 \(\mathcal Q_i\)、参考答案和完整训练历史提取信息需求 \(\mathcal D_i=\{d_1,\ldots,d_R\}\)，并将每项需求映射到 \(E_i\) 中的一个或多个可替代支持包 \(W_{rk}\subseteq E_i\)。候选来源集合的形式覆盖定义为

\[
\Phi_i(S)=
\bigwedge_{r=1}^{R}
\left(
\bigvee_k \mathbf 1[W_{rk}\subseteq S]
\right).
\tag{8}
\]

\(\Phi_i\) 仅用于离线缩小组合搜索空间。候选生成围绕支持包并集、替代证据组合、有限上下文增补以及完整 \(E_i\) 和空集合参照展开，得到至多 \(K\) 个来源集合 \(\mathcal S_K(i)\)。当候选池缺少某项必要来源时，保留缺失记录，不把参考答案注入 \(E_i\)，也不修改原始来源。未来查询、参考答案、需求标签和支持包均不会进入 ARC 的写入策略。**监督边界。** 监督定义在候选域 \(\Omega_i\) 之内：档案只能保留 \(\Omega_i\) 内的合格方案，其质量以候选生成的召回率为上界。协议以两个机制应对：候选池缺少必要来源时保留缺失记录，并在诊断中呈现（§8.5.2 证据保留率）；§3.7 的刷新循环允许重新枚举候选并重编译档案。策略不对 \(\Omega_i\) 之外的方案外推概率质量，故不对候选域外的方案作任何主张。

### 3.3.2 架构展开、真实构造与长期查询价值

对每个非空候选来源集合展开全部五种架构，并过滤构建上下文不可执行的组合（成本感知的级联加速版本见 §3.3.5）：

\[
\Omega_i=
\left\{
(g,S):
S\in\mathcal S_K(i),\ S\ne\varnothing,\ 
g\in\mathcal G,\ T_g(S)+L_G\le I_G
\right\}
\cup\{(\mathrm{Flat},\varnothing)\}.
\tag{9}
\]

空集合统一编码为 \((\mathrm{Flat},\varnothing)\)。对每个可执行方案，实际构造候选持久记忆状态

\[
m_i^{g,S}=\operatorname{Build}_g(S;G),\qquad
\mathcal M_i^{g,S}
=
\operatorname{Update}(\mathcal M_i^{-},m_i^{g,S}).
\tag{10}
\]

随后在**同一份**候选持久记忆上评价 \(\mathcal Q_i\) 中的全部未来查询。记单查询效用

\[
u_{i,q}(g,S)
=
\operatorname{Score}_d
\!\left(
F\!\left(q,\mathcal R(q,\mathcal M_i^{g,S})\right),
y_q^*
\right)
\in[0,1],
\tag{11}
\]

总体长期价值为其平均

\[
U_i(g,S)
=
\frac{1}{|\mathcal Q_i|}
\sum_{q\in\mathcal Q_i}
u_{i,q}(g,S),
\tag{12}
\]

并定义查询覆盖率

\[
\operatorname{Cov}_i(g,S)
=
\frac{1}{|\mathcal Q_i|}
\sum_{q\in\mathcal Q_i}
\mathbf 1\!\left[u_{i,q}(g,S)\ge\tau_q\right].
\tag{13}
\]

平均值可能被“对一半查询极好、对另一半极差”的方案掩盖，覆盖率则要求一份持久记忆对**足够多的未来查询都有效**；二者共同刻画“对多数查询都有高价值”。

**命题 2（覆盖率控制差服务查询比例）。** 若 \(\operatorname{Cov}_i(g,S)\ge\tau_{\mathrm{cov}}\)，则满足 \(u_{i,q}(g,S)<\tau_q\) 的未来查询至多占 \((1-\tau_{\mathrm{cov}})\) 比例。证明见附录 D.4。该命题把“对多数查询有效”从直观表述变为可验证的阈值性质；\(\tau_q\) 与 \(\tau_{\mathrm{cov}}\) 在开发集冻结。不同数据集使用各自冻结的官方或主评价协议；若一个训练更新单元对应不同类别的问题，则先按预先固定的规则在单元内聚合单查询效用，再计算式（12）与（13）。带查询权重的推广 \(\sum_j w_{ij}u_{i,q}\) 与按类别分层的阈值见附录 D。

审核依次检查结构合法性、来源忠实性和信息保留完整性。前两项直接检查构造结果；信息保留完整性检查候选记忆是否保留离线支持包所指向的必要信息。成功方案还需同时满足总体效用与覆盖率阈值：

\[
\operatorname{status}_i(g,S)=
\begin{cases}
\mathrm{PASS}, &
\text{三项审核均通过，且 }U_i(g,S)\ge\tau_U,\ 
\operatorname{Cov}_i(g,S)\ge\tau_{\mathrm{cov}},\\
\mathrm{FAIL}, &
\text{存在明确审核失败，或任一阈值不满足},\\
\mathrm{UNKNOWN}, &
\text{执行或审核信息不足，无法确定状态}.
\end{cases}
\tag{14}
\]

构造输出违反 schema 记为 FAIL；传输异常、服务中断或无法裁决的审核结果记为 UNKNOWN。每条离线记录保存 \((g,S,m_i^{g,S},T_g,C^{\mathrm{wr}},C_i,\{u_{i,q}\},U_i,\operatorname{Cov}_i,\operatorname{status}_i)\) 及执行配置。监督因此是**执行认证**（execution-verified）的：冻结构建器通过真实产出某个方案来认证它，冻结读取器与回答模型通过代表性查询集合认证其长期价值；一个更新单元因此贡献多个有效 \((S,g)\) 目标，而不是单一标签，也不额外指定唯一的“正确结构”或“正确子集”。

**注记（三层认证结构）。** 认证分三层、各由冻结组件完成：构建器认证**可执行性**（schema 合法、解析确定、预算可达），审核器认证**忠实性与信息完整性**，读取/回答模型在代表性查询集合上认证**长期效用**（均值＋覆盖率）。三层相互独立，“合法但不忠实”“忠实但无用”的方案在各自层被排除；UNKNOWN 表示认证信息不足，被排除出监督而非记为失败，因此训练信号不含被臆造的负例。

**注记（多正例的经验性质）。** 档案规模 \(|\mathcal W_b(i)|\) 是经验量：若档案常为单元素，边缘化目标退化为单终态似然（等价于 Single-positive 消融），方法优雅退化；档案规模分布与跨架构多正例比例单独报告（附录 E），作为多正例机制的经验前提。审核模板、模型分工、重复构建稳定性与人工抽查一致性见附录 D。

### 3.3.3 多预算成功档案

来源选择使用稳定来源标识递增的规范顺序。对于 \(S=\{e_{i_1},\ldots,e_{i_k}\}\)，令 \(i_1<\cdots<i_k\)、\(S_t=\{e_{i_1},\ldots,e_{i_t}\}\)，且 \(S_0=\varnothing\)。对完整方案 \((g,S)\)，预算可达性定义为

\[
\operatorname{Reach}_b(g,S)
=
\mathbf 1\!\left[
\max_{0\le t\le k}T_g(S_t)\le b
\right].
\tag{15}
\]

预算 \(b\) 下的成功档案（即已验证集，下文与摘要中的“已验证集”同义）为

\[
\mathcal W_b(i)
=
\left\{
(g,S)\in\Omega_i:
\operatorname{status}_i(g,S)=\mathrm{PASS},\ 
\operatorname{Reach}_b(g,S)=1
\right\}.
\tag{16}
\]

同一个 \(S\) 可以在多个架构下成功，同一个架构也可以对应多个有效来源集合。ARC 保留全部已验证成功终态，并复用相同构造记录建立不同预算的成功档案。档案为空的更新单元–预算对不产生正例监督，其覆盖率和失败原因单独统计。

### 3.3.4 选择过拟合及其抑制

成功档案是在候选域 \(\Omega_i\) 上对 \(\mathcal Q_i\) 做**多重比较**的产物：每单元至多 \(K\times|\mathcal G|\) 个方案参与筛选，真实长期价值不足的方案可能在 \(\mathcal Q_i\) 上偶然越线（偶然通过，spurious pass），若不加控制，策略将学习“对训练查询侥幸好”的方案。ARC 的抑制机制有五层：(i) 三层认证中**可执行性与忠实性/完整性两层与 \(\mathcal Q_i\) 无关**，偶然越线只能发生在效用层；(ii) 覆盖率要求同时服务足够比例的查询，其偶然概率呈指数尾界；(iii) 所有阈值在开发集冻结；(iv) 测试历史与查询从不参与监督构造或模型选择；(v) RQ3 在未见单元上以**独立候选协议**重建诊断档案复核。

**命题 3（偶然通过界）。** 视 \(\mathcal Q_i\) 为未来查询分布的 i.i.d. 样本。若某方案的真实单查询期望效用 \(\bar u_{\mathrm{true}}\le\tau_U-\delta\)，则 Hoeffding 给出 \(\Pr[U_i\ge\tau_U]\le\exp(-2|\mathcal Q_i|\delta^2)\)；覆盖率同理服从二项尾界 \(\Pr[\operatorname{Cov}_i\ge\tau_{\mathrm{cov}}]\le\exp(-2|\mathcal Q_i|(\pi_{\mathrm{true}}-\tau_{\mathrm{cov}})^2)\)（\(\pi_{\mathrm{true}}\) 为真实单查询有效率）。对 \(|\Omega_i|\) 取 union bound：

\[
\Pr[\exists\ \text{低价值方案入档}]
\le
2\,|\Omega_i|\,
\exp\!\left(-2|\mathcal Q_i|\min(\delta^2,(\pi_{\mathrm{true}}-\tau_{\mathrm{cov}})^2)\right).
\]

因此只要 \(|\mathcal Q_i|\gtrsim\log|\Omega_i|/\min(\cdot)\)，选择过拟合可控。这给出“代表性查询集规模”的统计角色：它不是越多越好的启发式，而是对候选域大小的对数级控制。适用域说明：该界在 \(\mathcal Q_i\) 为未来查询池的随机子样本时严格成立（对应 E.4 的下采样协议）；主配置取该历史全部训练侧 QA 时，界控制的是相对池内统计量的选择偏差，池外未来查询的外推由查询分布一致性假设覆盖（附录 D.4 讨论）。证明、查询间相关性的保守性讨论与 \(|\mathcal Q_i|\) 敏感性见附录 D.4/E.4。

### 3.3.5 成本感知编译：级联筛查

全量编译对每个候选执行真实构造与全查询评估，开销随 \(|\Omega_i|\) 线性（附录 G.3）。注意认证的一个不对称性：**入档需要全部检查同时通过，而淘汰只需一条可证的失败证据**。级联筛查（certified cascade screening）据此把认证组织为三级关卡：只改变“谁支付全额认证成本”，不改变入档规则，也不改变档案定义。

**Gate 0（零成本必要条件剪枝）。** 在调用构建器之前剪除两类方案。(a) 完整性必要条件失败：若存在信息需求 \(k\) 使支持包 \(W_{rk}\not\subseteq S\)，则所需信息不在候选来源内，忠实构造无法凭空补出（构建器仅允许使用给定来源，附录 J），完整性审核必然失败，\(S\) 对一切架构被剪；(b) 精确预算不可行：\(T_g(S)\) 由确定性序列化加 tokenizer 计数直接算出，不含生成调用，\(T_g(S)>b\) 的方案在该预算下不可达。两类剪枝均无假阴：被剪方案在全量协议下同样不会入档。

**Gate 1（Flat 代理探测）。** 对存活的每个内容子集 \(S\) 只执行一次最便宜的 Flat 构造，并在冻结的代理查询子集 \(\mathcal Q^0_i\subset\mathcal Q_i\)（\(|\mathcal Q^0_i|=m_0\)，均匀抽样，开发集冻结）上测量代理效用 \(\bar U^0(S)\)。若 \(\bar U^0(S)<\tau_U-\Delta\)，则 \(S\) 连同其全部架构展开被剪；否则进入 Gate 2。探测成本部分返还：Flat 构造产物即 \(g=\mathrm{Flat}\) 候选的正式构造产物，代理子集上的效用评估在 Gate 2 原样复用。

**Gate 2（全额认证）。** 存活内容子集展开全部预算可行架构，执行 §3.3.2 的完整认证（全 \(\mathcal Q_i\) 评估、三态审核、预算检查），入档规则与全量编译逐字相同。

正确性分两层。逻辑层：Gate 0 是入档必要条件的提前检查，剪除零假阴。统计层如下：记 \(\mu_F(S)\) 为 Flat 构造的真实平均效用（对未来查询分布取期望）。

**命题 9（级联筛查的漏检界）。** 视 \(\mathcal Q^0_i\) 为未来查询分布的 i.i.d. 样本（与命题 3 同一假定）。若 \(\mu_F(S)\ge\tau_U-\Delta\)，则 Gate 1 错剪 \(S\) 的概率满足

\[
\Pr\big[\bar U^0(S)<\tau_U-\Delta\big]\le\exp\!\Big(-2m_0\big(\mu_F(S)-\tau_U+\Delta\big)^2\Big);
\]

对全体满足条件的候选取 union bound 即得期望错剪数上界。\(\mu_F(S)<\tau_U-\Delta\) 的方案不享受该界：其入档价值只能来自非 Flat 结构，即架构收益 \(\gamma(S)=\max_g\mu(g,S)-\mu_F(S)>\Delta\) 的情形；统计层无法排除它们。工程保障：\(\Delta\) 在开发集上按全量编译日志观测到的 \(\gamma\) 分布上分位冻结，经验 \(\gamma\) 与档案一致性见 §8.6 与附录 E.10。证明见附录 D.4。

**与既有保证的关系。** 入档保证不变：任何入档方案仍通过 Gate 2 全额认证；命题 3 的偶然通过界只依赖入档侧的全额统计，原样成立。级联只作用于召回侧，命题 9 与命题 3 一召回、一入档，正交叠加。复杂度：真实构造调用从全量的 \(\sum_S|\mathcal G_b(S)|\) 次，降为 Gate 0 存活内容子集各一次 Flat 构造、加 Gate 1 存活者的其余可行架构构造数；多数候选在 Gate 0 或 Gate 1 被剪时接近线性节省。完整伪代码见附录 C.5（算法 C-2），开销实测见附录 G.3，消融见 §8.6。

## 3.4 内容优先的联合策略：先 S，后 g

ARC 的联合终态概率因子化为

\[
P_\theta(S,g\mid E_i,b)
=
p_\phi(S\mid E_i,b)\,
p_\psi(g\mid S,E_i,b),
\]

其中 \(\theta=\{\phi,\psi\}\)。该因子化与核心证据重叠假设一致：先过滤信息密度低、利用率低的边缘内容，得到值得长期保留的核心 \(S\)，再回答“对这份内容，哪种组织方式能让多数未来查询获得更高价值”。**监督仍作用于完整 \((S,g)\) 终态**（§3.5），因此因子化只决定决策顺序与参数化，不把 \(S\) 与 \(g\) 变成两个独立标签。

**为何内容优先是良定的。** 架构不是候选池的固有属性，而是对“已保留内容”的组织决策：同一 \(E_i\) 在保留不同 \(S\) 时最优 \(g\) 不同（保留桥接证据偏向 Graph，保留时间链偏向 Chain），即最优的 \(g\) 只有在 \(S\) 给定后才能识别，S→g 的因子化顺序与这一条件依赖一致；反向 g→S 则迫使来源策略在不知道组织方式时猜测内容（§8.4 以因子化消融检验该顺序）。核心重叠假设（§8.5.1）进一步保证统计上存在服务多数查询的核心 \(S\)，使第一阶段目标良定。我们不采用两个独立头（对 \(S\) 与 \(g\) 独立分类），因为独立认证的标签重新组合后不再是经认证的终态；配对关系必须由监督层保持（命题 5）。

### 3.4.1 序贯来源策略：S 如何被学习

冻结 embedding 模型编码候选来源及其元数据，轻量共享编码器得到候选集合表示 \(z_{E_i}\) 和来源表示 \(\{z_j\}\)。设 \(h_t\) 为规范前缀的递归状态，\(a\) 为来源动作或 STOP，来源动作评分为

\[
s_{t,a}
=
v^\top\tanh\!\left(
W_z z_a
+
W_h h_t
+
W_E z_{E_i}
+
W_\beta\beta_t
\right),
\qquad
\beta_t=
\left[
\frac b{I_G},
\frac{b-\hat T(S_t)}b
\right].
\tag{17}
\]

STOP 使用独立可训练表示。来源阶段尚不知道架构，因此掩码使用与架构无关的保守上界 \(\hat T\) 与裕量 \(m\)（命题 1）：

\[
\mathcal A_b(S_t)
=
\{j>j_t:\hat T(S_t\cup\{e_j\})\le b-m\}
\cup
\{\mathrm{STOP}\},
\tag{18}
\]

其中 \(j_0=0\)。保守掩码保证完成的 \(S\) 对全部架构都预算可行，精确可行性由式（5）在 \((S,g)\) 配对阶段最终确认；\(S=\varnothing\)（立即 STOP）规范对应 \((\mathrm{Flat},\varnothing)\)。保守性的代价是来源集合按最贵架构定尺寸：较便宜架构下原本可行的更大来源集合不会被来源束探索；由于架构专属字段仅相差数十 tokens，该损失很小，定量敏感性见附录 B.3。

**注记（两级掩码的必要性）。** 来源阶段架构尚未可知，而 \(T_g\) 依赖于 \(g\)：若在束内对每个候选扩展做逐架构精确计数，将把 \(S\) 的探索与 \(g\) 耦合，并为每次扩展付出 \(|\mathcal G|\) 倍 tokenizer 开销。保守上界 \(\hat T\) 将两者解耦：来源束在与架构无关的可行性概念下探索内容，架构头与档案在配对层做精确检查。两级不等于两个标准：硬预算始终由式（5）的精确计数最终裁决，保守级只提供安全探索边界；命题 1 保证该边界不放过任何越界方案。

策略在全部合法动作上归一化：

\[
\pi_\phi(a\mid E_i,b,S_t)
=
\frac{\exp(s_{t,a})}
{\sum_{a'\in\mathcal A_b(S_t)}\exp(s_{t,a'})}.
\tag{19}
\]

若 \(S\) 对应规范动作序列 \(a_1,\ldots,a_k,\mathrm{STOP}\)（\(k=0\) 时即空集合），则

\[
p_\phi(S\mid E_i,b)
=
\prod_{t=0}^{k}
\pi_\phi(a_{t+1}\mid E_i,b,S_t).
\tag{20}
\]

规范顺序仅用于给集合分配唯一策略轨迹；实际 Chain 顺序、Tree 层级、Graph 连接和 Cluster 分组仍由架构构建器实例化。训练时成功档案只定义正例集合，softmax 分母始终包含部署时可选择的全部合法动作。

**S 的信用分配。** \(S\) 的每一步 Pick 不依赖任何逐步骤标签，其梯度来自命题 5：每个已验证方案把概率质量沿自己的完整轨迹回传，混合权重 \(\rho_\theta\) 软性地决定“当前由哪些有效方案、以多大权重教这一步”；替代证据的多解性因此天然表现为多个轨迹对同一前缀的竞争与共享。可行性通过 \(\beta_t\) 与保守掩码进入评分，STOP 的时机由成功轨迹的终止位置示范。

### 3.4.2 内容条件的架构分布：g 如何被学习

给定已选内容 \(S\)，可行架构集合为 \(\mathcal G_b(S)=\{g\in\mathcal G:T_g(S)\le b\}\)；当 \(S=\varnothing\) 时规范取 \(\mathcal G_b(S)=\{\mathrm{Flat}\}\)。架构评分以来源策略的终态 \(h_k\)（即 \(S\) 的递归表示）、候选集合表示与预算特征为条件：

\[
p_\psi(g\mid S,E_i,b)
=
\operatorname{softmax}_{g\in\mathcal G_b(S)}\
u_g^\top
\left[
h_k;\ z_{E_i};\ \beta
\right],
\qquad
\beta=
\left[
\frac b{I_G},
\frac{b-\hat T(S)}b
\right].
\tag{21}
\]

内容条件使不同 \(S\) 获得不同的组织偏好：例如包含跨实体桥接证据的 \(S\) 偏向 Graph，时间连续性完整的 \(S\) 偏向 Chain，主题分散的 \(S\) 偏向 Cluster 或 Tree。

**g 的信用分配。** 架构头只从**已验证的 \((S,g)\) 对**获得梯度（命题 5）：对同一 \(S\) 多个架构同时成功时，softmax 在其间按 \(\rho_\theta\) 分配质量，学习“相对偏好”而非唯一标签；不可行架构由分母 \(\mathcal G_b(S)\) 以掩码排除，而不是以负例排除。

### 3.4.3 完整终态概率与使用一致性

完整结构化方案的概率为

\[
P_\theta(S,g\mid E_i,b)
=
p_\phi(S\mid E_i,b)\,
p_\psi(g\mid S,E_i,b).
\tag{22}
\]

式（22）是集合–架构终态概率：来源部分经规范顺序唯一分解，架构部分在可行集合上归一化。训练时不将动作空间缩减为成功档案中的后继动作。

**注记（使用一致性 / 闭环一致性）。** ARC 的三个环节共享同一机制，使“训练目标”与“部署使用”之间没有代理鸿沟：(a) 监督效用经**部署同款的** Update/Retrieve/Answer 路径测得（式（10）–（11））；(b) 解码分布即训练分布 \(P_\theta\) 本身（§3.6）；(c) 解码掩码与档案可达性 Reach_b 是同一可行性概念（式（5）/（15））。因此式（26）直接优化“部署后将被使用、且使用得好”的 \((S,g)\)；命题 6 给出该一致性与部署成功率之间的定量桥梁。

## 3.5 训练算法：多正例边缘似然

### 3.5.1 算法选择：为什么是边缘化似然

训练算法的候选有四类，ARC 选择监督式边缘似然，理由如下。(i) **RL**：需在线调用构建器/回答模型，方差高、采样贵，且标量奖励易被 hack；ARC 的离线档案已穷举认证，无需在线探索。(ii) **单标签交叉熵**：须在等价方案中任选其一，浪费已验证信息并引入任意性，且破坏配对。(iii) **对比学习**：需要负例；ARC 的 UNKNOWN 与未评估方案**不是负例**，构造负例会注入错误信号。(iv) **边缘化似然（ARC）**：把“这次构造成功由哪一个已验证方案造成”视为潜变量，对全部已验证方案的概率求和，既不用挑唯一标签，也不用造负例。

**命题 4（后验视角与精确 EM 梯度）。** 视成功事件为观测、\(z=(g,S)\in\mathcal W_b(i)\) 为潜变量，则观测似然为 \(M_\theta(i,b)=\sum_{\mathcal W}P_\theta(S,g)\)，潜变量后验恰为 \(\rho_\theta\)（式（24））。于是 \(\nabla_\theta[-\log M_\theta]=\mathbb E_{z\sim\rho_\theta}[\nabla_\theta\log P_\theta(z)]\)，即边缘似然的 E 步**无需采样**（档案显式枚举 \(\mathcal W\)）、M 步为对已验证轨迹的加权似然上升。训练因此是稳定、确定性的监督学习，却保留全部多正例信息。证明见附录 D.4。

### 3.5.2 边缘化总概率与配对保持

对 \(\mathcal W_b(i)\ne\varnothing\)，定义模型分配给全部已验证成功终态的概率质量

\[
M_\theta(i,b)
=
\sum_{(g,S)\in\mathcal W_b(i)}
p_\phi(S\mid E_i,b)\,
p_\psi(g\mid S,E_i,b).
\tag{23}
\]

基本目标为 \(-\log M_\theta(i,b)\)。该目标保留完整配对关系：若 \((S_1,\mathrm{Graph})\) 和 \((S_2,\mathrm{Chain})\) 成功，两者都获得正向监督，但由边缘标签重新拼接出的 \((S_1,\mathrm{Chain})\) 不会自动成为正例。定义成功条件分布

\[
\rho_\theta(g,S\mid i,b)
=
\frac{p_\phi(S\mid E_i,b)\,p_\psi(g\mid S,E_i,b)}
{M_\theta(i,b)},
\qquad
(g,S)\in\mathcal W_b(i).
\tag{24}
\]

**命题 5（边缘梯度与配对保持）。** 边缘目标对任意可微参数（含 \(\phi\) 与 \(\psi\)）的梯度为

\[
\nabla_\theta\left[-\log M_\theta(i,b)\right]
=
-\sum_{(g,S)\in\mathcal W_b(i)}
\rho_\theta(g,S\mid i,b)\,
\nabla_\theta
\left[
\log p_\phi(S\mid E_i,b)
+
\log p_\psi(g\mid S,E_i,b)
\right].
\]

即梯度质量只沿**已验证的完整 \((S,g)\) 轨迹**回传：来源动作与架构动作通过同一终态联合更新；未验证的重新组合不直接获得概率质量，也不被赋予失败标签。证明见附录 D.4。模型可以把概率集中到更容易稳定实现的成功方案，而不需要把多个有效方案压缩成一个唯一标签。

**命题 6（监督–部署桥梁）。** 若以采样方式部署 \((S,g)\sim P_\theta(\cdot\mid E_i,b)\)，则所构造记忆通过认证（即落入 \(\mathcal W_b(i)\)）的概率**恰为** \(M_\theta(i,b)\)；故 \(-\log M_\theta\) 就是采样解码下认证通过概率的 NLL。此处“成功”指通过与离线编译相同的冻结认证协议（使用一致性，§3.4.3 注记），而非端到端 QA 准确率本身；认证通过与端到端质量的对应由 RQ1 的主表结果与 RQ3 的双指标互证共同支撑。束/argmax 解码（§3.6）是该采样解码的方差缩减实例：当 \(M_\theta\to1\) 时补集质量 \(\to0\)，任何把质量放在高概率处的解码器都以概率 \(\to1\) 落在 \(\mathcal W\) 内。因此 SS-NLL（式（31））与 PASS@1（式（32））度量的正是同一量的“概率质量”与“解码实现”两侧，RQ3 以二者互证该桥梁。证明见附录 D.4。

### 3.5.3 成功方案之间的成本偏好与最终目标

记预算内最低已知成功生命周期成本为

\[
c_b^*(i)
=
\min_{(g,S)\in\mathcal W_b(i)}
C_i(g,S).
\]

ARC 对单个更新单元–预算对优化

\[
\boxed{
\ell_{i,b}
=
-\log M_\theta(i,b)
+
\lambda_c
\sum_{(g,S)\in\mathcal W_b(i)}
\rho_\theta(g,S\mid i,b)
\frac{C_i(g,S)-c_b^*(i)}
{c_b^*(i)}
}.
\tag{25}
\]

第一项提高成功方案集合的总概率；第二项只在已经成功的终态之间偏向较低生命周期成本，因此便宜但失败的方案不会获得奖励（命题 7 于附录 D.4 形式化该“先有效性、后成本”的次序）。\(C_i\) 由离线真实执行记录得到，写入开销和未来读取开销在成本日志中仍分别保留。

**推论 1（认证效用下界）。** 采样解码 \((S,g)\sim P_\theta(\cdot\mid E_i,b)\) 下，部署的期望效用满足

\[
\mathbb E\!\left[U_i(\text{部署方案})\right]\ \ge\ M_\theta(i,b)\cdot\tau_U,
\]

即式（25）第一项最大化的是部署期望效用的一个**认证下界**（档案内方案效用由准入式（14）保证不低于 \(\tau_U\)，档案外方案效用以 0 为下界）；第二项最小化认证集合内部按 \(\rho_\theta\) 归一的超额生命周期成本。训练因此可一句概括为：**最大化可证下界，然后在已认证方案内最小化成本**，而非优化任何代理指标。证明（两行）与紧致性讨论见附录 D.4；RQ3 对该下界做经验核验（§8.4.1）。

**注记（成本偏好的解释与训练/部署代理）。** \(\rho_\theta\) 是模型当前在成功方案上的条件分布，可视为“注意力分配”；成本项在该条件分布内部把质量拉向低开销方案，因此偏好作用于“已成功的条件分布”，而不作用于成功概率本身；有效性阈值（第一项与档案准入）与成本权衡（第二项）在目标中被显式分离。训练以 \(|\mathcal Q_i|\) 摊销写入成本，部署以真实复用次数 \(N\) 摊销；\(|\mathcal Q_i|\) 因而是分布感知度量下对 \(N\) 的估计，这一近似不影响有效性次序，只缩放偏好强度，\(N\) 敏感性见附录 G.1。档案为单元素时成本项为常数而不活跃，目标退化为单终态似然，与 §3.3 注记的优雅退化一致。

设 \(\mathcal I^+\) 为至少在一个训练预算下存在成功方案的更新单元集合，\(B_i^+\) 为单元 \(i\) 的非空成功档案预算集合，总目标为

\[
\mathcal L(\theta)
=
\frac1{|\mathcal I^+|}
\sum_{i\in\mathcal I^+}
\frac1{|B_i^+|}
\sum_{b\in B_i^+}
\ell_{i,b}.
\tag{26}
\]

**最终训练目标及其操作含义。** 式（26）即最终训练目标，可一句读作：“**先有效性、后成本、跨单元与预算归一**”。操作含义：(a) 有效性层：最大化认证效用下界 \(M_\theta\tau_U\)（推论 1），只给经执行认证的方案赋质量（命题 5/7）；(b) 成本层：在成功内部偏好真实使用更便宜的方案（命题 7）；(c) 归一化：单元与预算等权，避免档案规模偏置；(d) **明确不在目标中的**：无逐状态标签、无 UNKNOWN/未评估的负例、无 RL 奖励、无以标量混合质量与成本的项。优化器为 Adam，实现以 log-sum-exp 计算 \(M_\theta\)（附录 I 算法 3），梯度即命题 5 的 \(\rho\) 加权和；训练阶段只读取已编译档案，不重新调用构建器、读取器、回答模型或审核器。

## 3.6 写入时联合解码与查询时读取

写入时，ARC 先在来源动作空间中解码，再对每个完成的内容集合评分架构。来源束以 \(\log p_\phi(S\mid E_i,b)\) 为分数，按式（18）的掩码扩展 Pick/STOP，所有分支共享宽度为 \(w\) 的活动束，完成轨迹（Top-\(L\) 个 \(S\)）单独保留；随后对每个完成 \(S\) 计算全部可行架构的 \(\log p_\psi(g\mid S,E_i,b)\)，联合分数为两者之和。最终选择

\[
(\hat S_i,\hat g_i)
=
\arg\max_{(S,g)\in\mathcal H_{\mathrm{done}}}
\log P_\theta(S,g\mid E_i,b).
\tag{27}
\]

该“先筛内容、再按内容评架构、最后按完整联合概率比较”的过程避免第一阶段贪心错杀：例如来源分数较低的 \(S_1\) 在其最佳架构下的联合分数，可能高于来源分数较高的 \(S_2\)。解码期间不执行候选 Build 或语义审核，只有获胜方案被真正构造一次并写入长期记忆。

**命题 8（写入摊销，细化）。** 记一次写入成本 \(C^{\mathrm{wr}}\)、单查询读取成本 \(\bar C^{\mathrm{rd}}\)。服务 \(N\) 个查询的每查询生命周期成本 \(\mathcal C(N)=C^{\mathrm{wr}}/N+\bar C^{\mathrm{rd}}\)，\(d\mathcal C/dN=-C^{\mathrm{wr}}/N^2<0\)。对照“按查询构造”基线（每查询付一次 \(C^{\mathrm{wr}}\)，读取同一构造记忆，故读取成本同为 \(\bar C^{\mathrm{rd}}\)）：\(\mathcal C(N)\le C^{\mathrm{wr}}+\bar C^{\mathrm{rd}}\) 对一切 \(N\ge1\) 成立，且 \(N>1\) 时严格优于；若读取路径不同（\(\bar C^{\mathrm{rd}}\ne\bar C^{\mathrm{rd}\,'}\)），交叉点为 \(N^*=\left\lceil C^{\mathrm{wr}}/\left(C^{\mathrm{wr}}-(\bar C^{\mathrm{rd}}-\bar C^{\mathrm{rd}\,'})\right)\right\rceil\)（分母为正时），否则恒优。ARC-PQ 与 ARC 共享同一读取机制（同一冻结 Retrieve/Answer）；该机制下单查询读取成本的实测偏差为零时（G.1 代入交叉点公式核验），\(N=1\) 即不劣、优势随 \(N\) 单调增大。证明、\(N\) 敏感性与交叉点实测见附录 D.4/G.1。

**注记（查询时一次读取）。** 查询时 Retrieve 为非生成式索引访问，生成式调用恰为一次 Answer；“一次读取”指单次生成式读取，读取成本由回答上下文主导。空写入（\(\hat S=\varnothing\)）时读取路径回退到 \(\mathcal M_i^{-}\)，与规范终态 \((\mathrm{Flat},\varnothing)\) 一致；该路径不触发 ARC 的任何决策。

**算法 1　ARC 的离线学习、写入时构造与查询时读取**

```text
离线监督编译：
    对每个训练记忆更新单元 i：
        E_i ← C(X_i, M_i^-)
        S_candidates ← 利用离线未来查询与支持包引导的有限来源集合
        对每个候选 S 及其可执行架构 g：
            m ← Build_g(S; 冻结 G)
            M_candidate ← Update(M_i^-, m)
            对 Q_i 中的全部未来查询执行固定 Retrieve + Answer
            记录单查询效用、平均效用、覆盖率、写入/读取成本与三态审核
        按 PASS（审核 + 平均效用 + 覆盖率）与预算可达性建立各预算成功档案 W_b(i)
        （偶然通过控制：命题 3 的 |Q_i| 与阈值协议，§3.3.4）
    最小化式（26）（附录 I 算法 3：log-sum-exp 边缘似然 + 成本偏好），得到 H_theta

部署写入：
    新历史批次 X_i 到达
    E_i ← C(X_i, M_i^-)
    编码 E_i 与可观测元数据
    active ← 来源束（宽 w），按保守预算掩码（裕量 m）扩展 Pick / STOP
    对 Top-L 个完成 S：对全部精确预算可行的 g 计算 log p_ψ
    (S_hat, g_hat) ← 完整联合概率最高的 (S, g)
    若 S_hat 非空：
        m ← Build_g_hat(S_hat)
        M_i^+ ← Update(M_i^-, m)
    否则：
        M_i^+ ← M_i^-
    返回更新后的持久记忆 M_i^+

部署查询：
    q 到达
    R_q ← Retrieve(q, M_i^+)
    返回 Answer(q, R_q)
```

因此，昂贵的多候选、多架构 Build/Audit 只发生在离线监督编译；部署写入阶段只执行一个最终方案的构造；查询阶段不调用 \(H_\theta\)，也不重新选择 \(g\)、\(S\) 或重新 Build。候选数为 \(n\)、束宽为 \(w\) 时，写入时来源解码的候选评分与预算检查次数为 \(O(wn^2)\)，架构评分为 \(O(w|\mathcal G|)\)；具体编码缓存、构建延迟和生命周期摊销见附录 G。

## 3.7 档案扩充与策略刷新

ARC 的监督单位是已验证的记忆更新终态，因此训练档案可以随新的历史更新单元持续扩充。设第 \(k\) 轮训练更新集合为 \(\mathcal I^{(k)}\)。当获得新的历史批次 \(\Delta\mathcal I\) 时，沿用 §3.3 的候选生成、架构展开、真实构造和未来查询评价流程建立新档案；当在既有更新单元、**相同评价查询集合与相同执行协议**下发现额外成功终态时，可直接并入原有多正例集合：

\[
\mathcal I^{(k+1)}
=
\mathcal I^{(k)}\cup\Delta\mathcal I,
\qquad
\mathcal W_b^{(k+1)}(i)
=
\mathcal W_b^{(k)}(i)\cup\Delta\mathcal W_b(i).
\tag{28}
\]

随后从当前参数 \(\theta^{(k)}\) 初始化，在扩充后的档案上继续优化式（26）：

\[
\theta^{(k+1)}
=
\arg\min_\theta
\mathcal L
\!\left(
\theta;
\mathcal I^{(k+1)},
\{\mathcal{W}_b^{(k+1)}\}
\right).
\tag{29}
\]

只要评价定义不变，新增的成功终态只是让多正例集合变大，不需要重新指定唯一结构或唯一来源子集。若改变未来评价查询集合、构建器、读取器、回答模型、tokenizer、序列化规则或审核协议，候选方案的效用、成本或 PASS 状态可能同时变化，此时应重新验证受影响档案，而不能直接做集合并集。策略刷新属于离线过程；部署中的写入策略参数保持冻结，查询路径始终只访问已经构造好的长期记忆。
